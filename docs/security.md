# 安全与隐私规则

## 适用范围

涉及凭据、认证、会话、自服务页面、协议证据或真实网络实验时，必须先阅读本文。安全问题优先于当前教学节奏和功能范围。

## 数据分类

以下内容按敏感凭据处理：

- 密码、验证码、Cookie、`Set-Cookie`、CSRF Token 和 challenge；
- 完整认证 URL、认证请求参数和会话序列化数据；
- 可能包含身份或会话信息的原始自服务 HTML。

账号、姓名、手机号、IP 地址、MAC 地址和设备信息属于个人信息。测试、文档和日志只能使用虚构值或脱敏结果。

## 输入与存储

- 密码只从当前交互输入或操作系统凭据库读取；
- `configure` 使用隐藏输入，不在终端回显密码；
- 长期密码通过 `keyring` 保存，不得静默回退到明文文件；
- 自服务会话按凭据处理，不提交到 Git；
- 普通 TOML 只保存地址、超时、周期、运营商后缀和日志等级等非敏感值；
- 不把密码、验证码或会话值写入源码、普通配置、命令参数或长期环境变量。

## 输出与日志

默认只输出状态、错误类别、耗时和可行动建议。任何日志等级都不得输出密码、验证码、Cookie、CSRF Token、challenge、完整认证 URL、请求正文或原始响应正文。

账号、IP、MAC 和设备信息如需诊断必须脱敏。底层异常可能包含地址、URL 或系统信息，必须先转换为稳定的项目错误；`--debug` 也不例外。

## 测试、文档与协议证据

- 自动化测试只使用虚构账号、密码、地址、MAC、Token、challenge 和响应；
- 协议测试向量必须脱敏，并能在不连接真实校园网时运行；
- 不提交真实浏览器会话、网络抓包、验证码图片、截图或原始页面；
- 真实页面只允许提炼结构事实，不能把原文作为 fixture；
- 每条真实协议结论必须标记为已观察、已验证、推断或待验证。

修改认证协议前，必须先准备脱敏证据和失败测试，再修改生产实现。

## 真实网络实验

真实实验只能由学习者明确执行。记录仅保留脱敏状态码、主机类别、错误类别和耗时，不保存完整 URL、参数、响应正文或个人网络标识。

实验不得尝试绕过验证码，也不得执行自动下线、删除设备、修改资料或其他非 MVP 操作。

## 验证码与会话

自服务平台首次登录由用户人工输入图片验证码。程序不实现 OCR、不猜测验证码，也不复用无法确认有效的旧验证码。

会话失效时应重新认证；无法安全保存会话时明确报错，不得退回普通文件。

## 泄漏处置

发现疑似真实敏感信息时立即停止提交与传播，确认影响范围并通知学习者。不得通过普通追加提交假装从 Git 历史中删除已经提交的秘密。
