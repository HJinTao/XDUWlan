# XDUWlan 路线图

## 目标

第一版通过 Python 3.11+ 命令行程序学习并验证校园网状态探测、深澜 Portal 认证、自动重连、自服务数据采集、凭据保护和跨平台设计。

核心模型、状态机和协议纯逻辑应与 CLI、操作系统及具体网络库解耦，为后续跨语言实现保留稳定契约和脱敏测试向量。

## MVP 范围

| 切片 | 状态 | 用户结果 |
| --- | --- | --- |
| `status` | 已完成 | 识别在线、需要认证、网络不可用或未知状态 |
| `configure` | 下一步 | 交互输入账号和密码，密码保存到系统凭据库 |
| `login` | 计划中 | 执行一次 Portal 认证并独立验证联网结果 |
| `watch` | 计划中 | 前台周期探测，掉线后认证并对临时失败退避 |
| `account` | 计划中 | 人工输入验证码后读取在线会话、设备和套餐信息 |

第一版还需要完成日志脱敏、macOS 实测、Windows/Linux 自动测试与 CLI 验证，以及可复现的打包说明。

## 明确不包含

- 图形界面、系统托盘、开机自启和后台系统服务；
- 自动识别或绕过验证码；
- 多账号并行、云同步和远程数据上传；
- 自动下线、删除设备或修改自服务资料；
- 长期流量图表、通知和运营分析。

## 切片验收

### `status`

已完成 DNS、TCP、HTTP 适配器、Portal 信号分类、完整探测服务、配置读取以及中文、JSON 和 debug 输出。自动化测试不依赖真实校园网，真实结论仍以脱敏实验为准。

### `configure`

密码通过系统凭据库保存；交互与错误输出不泄漏密码；凭据后端不可用时明确失败，不回退到明文文件。

### `login`

使用脱敏向量验证协议纯逻辑；只有确认需要认证时才读取凭据；成功响应后重新探测；凭据错误、临时网络错误和协议变化可以区分。

### `watch`

复用探测与登录能力；临时失败使用有上限的退避和抖动；不可重试错误停止；`Ctrl+C` 可以结束前台循环；测试不真实等待。

### `account`

Portal 认证与自服务保持独立；首次登录由用户人工输入图片验证码；会话失效可以重新登录；解析器只接收脱敏 HTML，并在页面结构变化时给出明确错误。

### 交付

macOS 完成受控实测；Windows 和 Linux 至少完成自动测试与 CLI 验证；日志和错误输出通过敏感信息检查；打包与开发步骤可复现。

## 实施原则

每个切片按认知边界拆成递进子任务。具体文件、符号、测试和实现只在子任务开始前对齐，不提前把未来切片固化为容易过期的逐步计划。
