# 连通性检测与 Portal 识别

## 文档范围

本文只记录任务三通过虚构单元测试和本地 loopback 服务器得到的脱敏证据。它不记录真实账号、Cookie、认证参数、完整认证 URL 或原始校园网页面。

证据标签沿用协议目录：**已验证**、**已观察**、**推断**。

## 已验证：基础通信路径

证据：自动化单元测试与本地 `ThreadingHTTPServer` 集成测试。

```text
URL 主机名
→ 操作系统名称解析得到地址候选
→ TCP 连接 IP 地址和端口
→ HTTP GET 请求
→ 保留状态码、Location 和有限正文
→ 纯函数分类
```

- `socket.getaddrinfo(..., type=SOCK_STREAM)` 可以产生后续 TCP 使用的地址记录；
- TCP 成功、超时和其他系统错误可以转换成稳定观察；
- HTTP 客户端可以禁止自动跟随重定向，并保留原始 302 与 `Location`；
- HTTP 响应正文可以按声明字符集解码，并限制为最多读取 65,536 字节；
- 底层连接与请求异常正文不进入面向上层的说明。

这些事实验证的是 Python 标准库适配器与本项目抽象，不是特定校园网的线上行为。

## 已验证：当前分类契约

证据：纯分类测试与本地服务器集成测试。

- 连通性端点返回 `204` 时分类为 `ONLINE`；
- `3xx` 的 `Location` hostname 精确匹配已知 Portal 主机集合时分类为 `PORTAL_REQUIRED`；
- `200` 正文大小写无关地包含 `srun_portal` 时分类为 `PORTAL_REQUIRED`；
- 普通 `200`、未知主机重定向、网络失败、缺失或畸形 `Location` 返回 `UNKNOWN`；
- 主机判断基于结构化 hostname，不接受查询参数或 URL 其他位置中的字符串伪装。

本地服务器已验证三条受控路径：

```text
/online → 204 → ONLINE
/portal → 302 → 不跟随 → PORTAL_REQUIRED
/login  → 200 + srun_portal → PORTAL_REQUIRED
```

## 推断：真实校园网使用方式

以下内容尚未通过脱敏校园网实验验证：

- 当前配置的连通性端点在西电校园网内是否稳定返回预期的 `204`；
- 未认证状态是否稳定返回指向配置 Portal 主机的 `3xx`；
- 当前深澜登录页面是否稳定包含 `srun_portal` 特征；
- IPv4、IPv6、不同运营商出口或不同校区是否表现一致；
- 是否需要多个探测目标降低单点故障造成的误判。

在获得真实证据前，这些规则是可测试的实现假设，不写成已观察事实。

## 安全与记录规则

- 真实实验只记录脱敏后的状态码、主机类别、耗时和结论；
- 不保存完整重定向 URL、查询参数、认证页面正文、Cookie 或个人网络标识；
- 自动化测试只使用 loopback、保留示例地址和虚构域名；
- 真实网络实验不进入自动化测试，避免环境依赖和敏感数据进入仓库。

## 后续验证问题

任务四接入 `status` 后，在用户明确执行受控实验时验证：

1. 已认证网络下，配置的探测端点返回什么状态码？
2. 未认证网络下，第一跳响应的状态码和脱敏 hostname 类别是什么？
3. 禁止自动重定向后能否稳定保留 Portal 证据？
4. DNS、TCP 和 HTTP 分别失败时，`NetworkState` 应如何区分本地网络故障与互联网不可达？
