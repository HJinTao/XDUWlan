# 0004：采用分层项目记忆与按需加载

## 状态

已接受。

## 背景

项目需要跨会话保持教学与开发连续性，但现有进度、交接、规格、计划和学习文档重复记录相同事实。新会话必须读取大量历史流水，文档之间还会因更新节奏不同产生冲突。

文档重构必须同时解决两个问题：减少默认上下文，以及保留足以继续指导开发的项目记忆。

## 决策

采用分层记忆，并让每类文档只有一个职责：

- `AGENTS.md` 保存稳定的协作契约和记忆管理规则；
- `docs/current.md` 保存当前工作记忆；
- `docs/roadmap.md` 保存产品范围、能力状态和后续里程碑；
- 架构、安全、决策和协议文档保存对应的长期知识；
- Git 保存逐轮开发历史和精确变更。

新会话默认只读取 `AGENTS.md` 和 `docs/current.md`，再根据当前任务索引按需读取源码、测试和专项文档。两份默认入口合计控制在约 200 行以内。

## 工作记忆生命周期

进行中的子任务详细记录目标、文件与符号、调用关系、知识前提、RED/GREEN、下一责任人、阻塞和下一动作。状态没有变化时不重复追加叙述。

切片完成后，将详细过程压缩为能力、接口、测试证据、决策和遗留风险。逐轮测试数量、格式整理和对话经过不进入长期活文档；需要追溯时使用 Git。

## 教学与实现粒度

切片按认知边界拆成循序渐进的子任务，每个子任务开始前单独对齐。首次出现且理解负担较高的概念可以使用较小单元；已经掌握的模式和同一职责内的相关分支应合并。

一个子任务默认以一次 RED 覆盖完整行为，再由学习者一次实现到 GREEN。不得按单测试、单方法或单异常机械拆步，也不得为了减少轮次把多个独立的新概念一次交给学习者。

## 验证与沟通节奏

- 小步只运行目标测试；
- 共享接口变化时运行受影响测试；
- 完整回归只在跨模块改动、切片完成或提交前运行；
- 非阻断边界只记录，不自动扩展测试或实现；
- 过程更新只在架构对齐、RED、等待实现、审查问题、GREEN 或阻塞时出现；
- 文档只在事实或工作状态变化时更新。

## 文档处置

删除面向课后复习的 `docs/learning/`。将 `docs/progress.md` 与 `docs/session-handoff.md` 合并为工作记忆。旧规格与逐任务实施计划中的长期有效内容提炼到路线图、架构、安全、决策和协议文档后删除。

两份 HTML 可视化继续保留，但在 Markdown 重构后单独审查文字内容；重点提高信息密度和可读性，不以重做布局为目标。

## 后果

默认上下文显著缩小，进行中的工作仍可跨会话恢复，长期决策和协议证据也不会丢失。维护者必须及时更新 `docs/current.md`，并避免把临时状态重新复制到长期文档。
